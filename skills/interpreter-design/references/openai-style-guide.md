# OpenAI Style Guide

## Scope

- Use the OpenAI website and ChatGPT product surfaces only.
- Ignore the OpenAI developer platform.
- Design for non-developers.
- Stay ultra-minimal and utilitarian.

## What to copy

- One clear focal action.
- One centered instruction block when the task is simple.
- Quiet navigation.
- Thin lines and light separators.
- Large whitespace.
- Short headings.
- Plain language.
- Few visual layers.
- Calm visual balance.

## What to avoid

- All-caps titles or eyebrow labels.
- Container-on-container layouts.
- Badge soup.
- Dense settings grids.
- Pinched rows and cramped text.
- Lopsided layouts where one side does all the work.
- Technical or internal jargon.
- Visible implementation detail such as logs, file paths, IDs, endpoints, protocol names, or process phases.
- Explanations that repeat the heading.
- Decorative chrome that does not help the task.

## Theme rules

- Use the app's existing CSS variables and theme tokens.
- Do not invent a separate light palette or dark palette when the app already defines them.
- Keep surface, text, border, and accent choices inside the existing variable system.
- Check both themes after layout and copy changes, not just at the end.

## Copy rules

- Write for someone who is not technical.
- Write for an average HR admin, recruiter, coordinator, or operations person.
- Prefer common words over product or engineering jargon.
- Keep helper text to one short thought when possible.
- Make the action label concrete and direct.
- Do not surface technical detail that requires engineering knowledge to interpret.

## Reduction checklist

1. Remove one container.
2. Collapse duplicate helper text.
3. See if one centered instruction block is enough.
4. Cut jargon.
5. Make the primary action obvious.
6. Check that the top of the screen feels balanced, not squeezed.
7. Remove any visible logs, IDs, endpoints, paths, or protocol names.
8. Make sure the screen still feels like a product for regular people, not a tool for operators.
