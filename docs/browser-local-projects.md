# Browser-local projects (bounded proof)

The static browser-project entry is a **generic capability proof**, not a browser port of the Electron/Node/Rust agent. Build it with `pnpm exec vite build --config browser-project/vite.config.ts` and serve `dist-browser-project/` over HTTPS. During development, `pnpm exec vite --config browser-project/vite.config.ts` serves `/browser-project/`. It needs no Workstation sidecar or operator-run project process.

Project files live in origin-private file system storage under `interpreter-projects/<project-id>` and are subject to quota/eviction. The sample UI can export a bounded JSON backup. The broker validates relative paths and revision conflicts; `applyApprovedEdit` requires explicit approval. The sample suggestion is **deterministic**, not an inference call. `BrowserWorkerHost` runs only a same-origin, versioned worker asset, caps pending calls, and times out requests; project text never becomes worker source. The sample worker demonstrates local state/sequence, not a scientific model. The live preview is an opaque-origin sandboxed frame with no file bridge and a restrictive network CSP. Preview refresh after a save is not Vite hot-module replacement.

This proof does **not** support Node package installation, an arbitrary shell, browser OAuth, a model-backed agent, imported untrusted JavaScript as a tool, scientifically valid simulation, cross-tab atomic writes, or mobile compatibility. Native OIX/Electron/Node do not run unchanged in this tab. No credentials are copied from the installed app. A production visitor-model connector requires documented browser-origin registration, consent, token custody, CORS and entitlement evidence; it must not silently use an operator relay or API billing. Production runtime packages and browser compatibility require independent license and platform testing.

Project-specific simulations and presentation assets belong outside Workstation. A project can provide a pinned same-origin worker implementing an explicit stateful contract, then bind its own UI to these generic file/approval/worker interfaces. Do not put private project code, content, benchmarks or correspondence into this repository.

Verification: `pnpm exec vitest run --config vitest.config.ts src/browser-project/project.vitest.test.ts` and an actual Chromium browser against the static build: edit → approve → iframe refresh → reload persists → local worker sequence increments. Inspect network activity before claiming no operator compute or source upload. The browser requires a secure context for OPFS; loopback development is a secure context exception.
